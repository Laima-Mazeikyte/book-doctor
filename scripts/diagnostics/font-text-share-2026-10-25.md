# Approximate font share by page (2026-10-25)

Percentages are based on non-whitespace characters in rendered HTML text, including navigation and form placeholders. They describe configured font-face use, not visual area. The first four font columns are Bespoke Serif faces. `-` means zero in the sampled state; rounding can produce totals slightly different from 100%.

Samples use a synthetic signed-in account with ten ratings, two bookmarks and three dismissals. Catalog strings come from the public Top 100, with working cover images; browse/bookshelf lists contain ten books, and recommendations/shortlist contain seven. Collapsed UI and image lettering do not count. Lab figures cover HTML controls/instructions, excluding labels drawn into canvas/WebGL. Exact shares vary with content and state.

## Font roles

| Font face              | Typical use                                                                  |
| ---------------------- | ---------------------------------------------------------------------------- |
| Bespoke Serif Light    | Body copy, descriptions, summary text, fallback-cover authors                |
| Bespoke Serif Regular  | Captions, supporting messages, drawer/empty-state details                    |
| Bespoke Serif Bold     | Book-detail titles, drawer titles, subsection headings, missing-cover titles |
| Bespoke Serif Variable | Page headings and content headings across different weights                  |
| Inter Regular (400)    | Navigation, buttons, inputs, filters, FAQ questions                          |
| Inter Medium (500)     | Medium-weight labels, including small book-detail labels                     |
| Inter SemiBold (600)   | Emphasized filter and lab controls                                           |

## Interpretation and limits

Book-cover artwork is not HTML text. Therefore the normal browse/bookshelf grids can have zero Bespoke Bold characters even though Bold is available for cover failures and summary drawers. Shortlist layouts expose different content on mobile and desktop, so their shares can differ substantially. The book-detail percentages describe one representative catalog entry; longer descriptions change the mix.

The CSS face is not always the actual rendered face. In this cold-load sample, some Inter 600 text in filtered recommendations rendered as Segoe UI SemiBold. Inter retains its existing `font-display: optional` policy, which permits a fallback on that load. Actual font samples are kept alongside the assigned-face counts in [the result data](font-text-share-2026-10-25.json). See [MDN on font-display](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face/font-display).

The measurement walks text nodes with layout boxes, excludes hidden/clipped content, and counts the currently selected option/input text separately. Words are used to approximate partially clipped text. A font-family/weight sample is checked with Chromium rendered-font inspection. This is a reproducible approximation for font inventory, not a glyph-perfect census, real-user traffic mix, or typographic-area measurement. No real account data, tokens, or writes were used.
